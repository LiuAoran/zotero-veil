# 阅读器刷新循环修复验证

日期：2026-10-27。Zotero 10.0.6，macOS 27.2，Apple Silicon。

## 结论

在独立空库、仅安装 Veil 1.0.4 和测试通信桥、打开合成空白 PDF 的情况下复现持续高 CPU。阅读器 applyReader 调用计数先达到 8,443，继续增长至 21,638。原实现捕获所有 load 事件，并无条件重写自身 style.textContent；Gecko 的样式加载事件再次进入该处理，形成循环。

修复只监听 iframe 的 load，排除样式及图片加载；样式文本未变时不写入，保留设置变化和新 PDF iframe 的样式更新。

## 实测

同一独立测试进程 PID 54981：
- 原始 1.0.4，空白 PDF，玻璃关闭：CPU 112.4%。
- 临时阻断重复更新后，调用计数停止增长。
- 装入完整修复包，玻璃关闭：CPU 0.6%。
- 开启玻璃并关闭、重开 PDF 后：CPU 0.8%；观察期间 applyReader/refresh 计数无新增。

这些是 ps 的时点读数，不是平均功率、耗电量或温度测量。通信桥有低频轮询开销；未据此声称所有场景均无性能问题。

## 回归

- npm test：32 项通过，新增模拟样式 load 的循环回归、重复刷新幂等性、iframe 加载、种子色修改和监听清理测试。
- Zotero 真实运行时 API 检查：浅色/深色 × 玻璃开/关，阅读器样式始终一个；PDF 边缘样式开时一个、关时零。
- 重开 PDF 后阅读器及边缘样式各一个，未恢复循环。
- 使用独立临时 profile 和合成空白 PDF，无日常库写入；未修改其他插件。
- 本轮不是物理鼠标操作测试，也未执行电池续航或温度基准。
